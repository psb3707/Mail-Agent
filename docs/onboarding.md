# mail-agent — 신규 개발자 세션 온보딩

> 이 문서는 `deepwork-mail` 워크스페이스에서 새 개발자 세션을 시작할 때
> 읽고 따라야 하는 진입 안내다. **워크스페이스 신규 세션을 열면 맨 처음
> 이 문서를 읽는다.** 프로젝트 설계·스토리는 설계 문서, 실무 상태는
> `handoff.md`, 단계별 계획은 플랜 문서가 담당하므로 이 문서는
> "지금 어디까지 왔고, 뭘 하면 되는지"로 좁힌다.

---

## 1. 프로젝트 한 줄

> **메일함을 도착순이 아니라 건(件) 단위로 보게 하는 레이어.**

사내 해커톤 출품작. 가상 메일 400통을 모킹해 에이전트 동작을 시연하는 PoC.
메일은 "통"으로 도착하지만 일은 "건"으로 돌아가므로, 통→건 재조립 판단에 AI를 쓴다.

핵심 명제: 메일함은 보관만 하고 정리는 안 한다 → 그 정리 비용을 사람이 매번 낸다.

## 4. 전역 제약 (어떤 작업이든 되새길 것)

| 제약 | 내용 |
|---|---|
| **원본 무수정** | `data/mails.json`·`data/attachments/` **절대 수정 금지** — 시연은 "무수정" 전제 |
| **저장 인메모리** | DB(SQLite) 금지 — 동적 구조는 세션/인메모리만, 영속화 비범위 |
| **라이브 기본·캐시 폴백** | LLM 라이브 호출이 기본, 캐시는 네트워크 장애 시 자동 폴백 전용 |
| **순서 무관·멱등·증분 편입** | 분류 결정 근거는 내용, 시각은 보조 단서. 재실행 시 건 ID·결론 불변 |
| **비건 처리** | 건에 안 붙는 357통을 무시하지 않고 "알림"/"기타" 섹션으로 표시 |
| **근거 인용** | 답만 주지 말고 문서 속 실제 값(금액·일자·버전·업체)을 인용 — 데모의 심장 |
| **구조 유지** | `app/`·`scripts/` 구성 그대로. 새 폴더 임의 생성 금지 |
| **AI 경계** | 규칙으로 되는 판단(정규화·토큰·추출)은 규칙, 규칙 불가 판단(같은 건·버전)만 AI |

## 5. 다음에 할 일 (우선순위순)

### 5-1. 색인 안정화 — ✅
- 회신 그래프를 뼈대로 9개 건을 만들고, 표기 정규화·업무 생애주기·시간 근접성으로 끊긴 메일을 보완한다.
- 일반 메일이 대표어를 오염시켜 오분류가 연쇄 증폭되지 않도록 확장 전 대표어를 고정한다.
- `N_CX` 6통, `Next W` 4통을 포함한 사안 메일 43통과 비건 메일 357통이 정답 세트와 일치한다.
- `_case`는 평가 테스트에서만 사용하며, 제거한 입력에서도 동일한 결과가 나오는 테스트가 있다.

### 5-2. D1-7 발표·리허설 마무리 — ⚠️
- `slides/발표-뼈대.md`를 실제 발표 자료로 다듬고 4장면을 오프라인 폴백에서도 리허설한다.
- 대본 밖 예비 질문 3개와 필수교육 질문의 답 품질을 확인한다.

### 5-3. 문서 상태 동기화 — ✅
- `README.md`·개발/QA 온보딩·`handoff.md`·데이터 스키마의 오래된 상태와 수치를 실제 구현에 맞췄다.

## 8. 워크스페이스 관례

- **위키 정리**: 작업 중 재사용 가능한 지식(의사결정·인사이트·절차)이 생기면

  (일회성 로그·PR 번호·임시 경로는 기록 금지)
- **한국어**: UI·답변·커밋 메시지의 출력 언어는 한국어가 기본.
  단, 커밋 메시지 인코딩 문제(Windows)를 피하려면 한글보다 영문 메시지를 권장.
