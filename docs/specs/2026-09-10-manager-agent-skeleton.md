# 관리 Agent 골격 설계 — 대화 맥락 + 도구 호출 + 분류AI 어댑터

> 지시 008 산출물 · 2026-09-10 · 개발자3
> 역할: "메일 관리 도우미 Agent"(챗 방식)의 **골격**과 **분류AI 연동 인터페이스**를
> 같은 레포 안에 정의한다. 분류AI 본체는 동료 PC가 개발하되 단일 레포로 통합되므로,
> 이 문서가 그 **경계 규약(계약)**을 결정한다.

## 1. 목적과 범위

- **목적**: 사용자와 챗으로 대화하며 맥락을 이해하고, 검색·답장 초안·요약·알림 정리를
  돕는 관리 Agent의 뼈대를 만든다.
- **이번 단계 범위**: 설계 확정 + 인터페이스 계약 + **스텁 수준 골격 코드** + 목(mock) 스모크.
  분류AI 본체·메일 DB 실제 도입은 이번 범위가 아니다 (총괄 PM 결정 후 확장).
- **비범위**: 규칙 엔진, DB 영속화, 사용자 인증, 실제 LLM 튜닝.

## 2. 구성 (4 컴포넌트)

| 컴포넌트 | 책임 | 대표 심볼 |
|---|---|---|
| 대화 맥락 관리 | 사용자 메시지·이전 대화를 유지해 "지금 무슨 일을 하는가"를 안다 | `ConversationContext` |
| 도구 호출 루프(오케스트레이션) | 맥락을 읽고 적절한 도구를 골라 호출, 결과를 요약에 넘긴다 | `ManagerAgent.run()` |
| 분류AI 어댑터 | 분류AI(동료 PC 코드)와의 **경계**. 분류 결과를 함수/데이터로 받아온다 | `ClassifierAdapter` |
| 응답 생성 | 사용자에게 반환할 최종 텍스트(답변·초안·요약)를 만든다 | `respond()` |

오케스트레이션은 LLM이 도구를 골라 호출하는 **에이전트 루프**를 담당한다.
골격 단계에서는 도구 선택을 결정하는 함수(`_pick_tool`)를 스텁으로 두고,
목 어댑터로 전체 루프가 돌아가는지 확인한다.

## 3. 분류AI 인터페이스 계약 (핵심)

분류AI는 별도 서버가 아니라 **같은 레포의 모듈**이다. 따라서 프로세스 간 경계가 아니라
**코드 인터페이스**로 정의한다. 어댑터(`ClassifierAdapter`)가 이 계약의 구현자이며,
분류AI 구현이 도착하면 이 어댑터만 실제 구현으로 바꾼다.

| 함수 | 시그니처 | 반환 | 역할 |
|---|---|---|---|
| `get_tree()` | `() -> dict` | 건 트리 `{"root", "children": [...], "cases": [...]}` | 분류 전체 구조 조회 |
| `get_case_emails(case_id)` | `(case_id: str) -> list[dict]` | 건에 속한 메일 메타 리스트 | 건 타임라인 조회 |
| `get_attachment_text(attachment_id)` | `(attachment_id: str) -> str` | 첨부 추출 전문 | 근거·요약에 사용 |

**주의**: 이 함수들은 **분류AI 구현이 붙기 전까지는 스텁/목으로만** 존재한다.
실제 분류 로직을 이 파일에서 구현하지 않는다 (지시 008 제약).

## 4. 저장 경로 결정

- 골격 코드: **`agent/`** (레포 루트의 최상위 패키지). 이유:
  - 기존 PoC 서빙(`app/`)과 **패키지 경로가 분리**되어 충돌이 없다 (단일 레포 원칙).
  - `app/`은 FastAPI 서빙 전용이고, 관리 Agent는 별도 도메인이므로 분리 경로가 명확하다.
- 설계 문서: `docs/specs/2026-09-10-manager-agent-skeleton.md` (본 문서)
- 테스트: `tests/test_agent.py`
- 레포 루트 하나에서 `pytest tests/`로 기존 테스트와 함께 실행된다.

## 5. 에이전트 루프 (순서)

```
사용자 입력
  → ① ConversationContext에 메시지 추가 (대화 유지)
  → ② ManagerAgent.run(): _pick_tool로 적절한 도구 선택
       (분류AI 조회 / 응답 생성 / 초안·요약 중)
  → ③ 선택한 도구 호출 (분류AI 어댑터 또는 응답 생성)
  → ④ 결과를 ConversationContext에 기록
  → ⑤ respond()로 사용자에게 텍스트 반환
```

골격 단계에서 LLM 호출이 없어도(라이브 기본 원칙) 루프가 도는 것을 목으로 검증한다.
실제 LLM 연동은 `app/llm.llm_call` 규약을 재사용한다 (`callable(prompt, cache_key="") -> str`).

## 6. 단일 레포 통합 규칙

- `agent/`는 `app/`을 import하지 않을 수 있지만, 공통 `llm_call` 규약은 따른다.
- 새 파일은 `agent/`·`tests/`·`docs/specs/` 안에서만.
- 원본 데이터(`data/mails.json`·`data/attachments/`)·`data/indexed.json` 읽기 전용.
- 라이브 LLM이 기본, 캐시 폴백 전용 (기존 원칙 유지).

## 7. 이후 확장 (총괄 PM 지시 후)

- 분류AI 실제 구현이 도착하면 `ClassifierAdapter`를 실제 모듈 호출로 교체.
- 메일 DB 저장 계층이 결정되면 어댑터/루프를 그에 연결.
- 답장 초안·요약·알림 정리 도구를 `_TOOLS`에 추가 확장.
