# mail-agent — 해커톤 발표 뼈대 (10분)

> 목적: 4장면 데모(문제 → 시연 → 왜 AI → 실용성)의 발표 흐름을 고정한다.
> 각 슬라이드의 **발표 멘트**는 입말로 적었다. 시연 영상/라이브와 함께 진행한다.

## S0 — 오프닝 (0:00~0:30) · 30초

> "메일함이 400통 쌓여 있습니다. 오늘 이 안에서 필요한 걸 찾아보겠습니다."

**핵심**: 제목만으로는 '무슨 일이 있었는지'가 보이지 않는다는 체감 먼저.

---

## S1 — 문제: 메일함은 '통' 단위로 쌓인다 (0:30~1:30) · 1분

> "메일은 통 단위로 도착하지만, 일은 건 단위로 돌아갑니다. 정리 비용을 매번 사람이 냅니다."

- **증거**: 실제 사내 메일 제목 30개 화면 (회사명만 가림)
- **심사자 참여**: "지난 분기 B사 견적서, 무엇을 검색하시겠습니까?"
- 검색 실패 체감 — `N_CX` → 누락, `견적` → 판별 불가

| 증상 | 본질 |
|---|---|
| 쌓이기만 함 | 도착 로그는 원래 쌓임. 정리 기준(건)이 없음 |
| 찾을 수 없음 | 결정·합의가 로그에 흩어져 건 단위 조회 불가 |
| 용량 부족 | 건 단위로 봐야 지울 수 있음 |

---

## S2 — 시연: 건 단위로 재조립 (1:30~3:30) · 2분

> "같은 메일함을 건 단위로 보면, 다섯 통이 하나의 사안으로 보입니다."

**데모 (라이브)**:
1. 도착순 ↔ 건 단위 토글
2. `Project N_CX` 건 카드 — 업체 선정 타임라인 + 첨부 위치
3. 신메일 수신 → 같은 건에 자동 편입 (`/classify`)

**화면 요소**: 건 카드(최신 발신·본문) / 타임라인 / 첨부 / 비건 "알림·기타" 접기

---

## S3 — 시연: 자연어 질문 → 근거와 함께 답 (3:30~5:30) · 2분

> "그럼 찾는 게 이제 한 번의 질문입니다."

**데모 질문 1**: "N_CX 외주 견적 최종 얼마였지?"
→ **N_CX_UIUX_견적취합_v3.xlsx · (주)디자인랩스 48,500,000원(VAT 별도) · 2026-05-12 3차 취합본**

**데모 질문 2**: "워크숍 버스 몇 시에 어디서 타?"
→ **NextW_버스배차_최종명단.pdf · 3호차 · 08:30 · 본사 정문**

> **핵심**: 답만 주지 않고, 문서 안의 실제 값(금액·일자·버전·업체)을 '왜 이것인가'로 인용.

---

## S4 — 왜 AI인가: 규칙이 불가능한 판단 (5:30~6:30) · 1분

| 판단 | 왜 규칙이 안 되나 |
|---|---|
| 같은 건인가 | 제목 표기 흔들림(N_CX·N CX·Project N CX), 스레드 끊김(RE:/FW:), 축약 |
| 같은 문서의 어느 버전인가 | `최종_최종_진짜최종.xlsx`의 보편적 고통 |

- **장면 4 하이라이트**: 버전 계열 → 최신본(a001 v3) + 달라진 항목(단가 산정 기준)
- 규칙은 정규화·토큰·추출에만, **판단은 AI에만**

---

## S5 — 실용성·운영 (6:30~7:30) · 1분

- **무수정 원칙**: 원본 메일함·첨부는 절대 수정 안 함 (시연 전제)
- **저장 인메모리**: DB 없음 — PoC 비용 최소
- **라이브 기본·캐시 폴백**: 네트워크 장애 시에도 데모 완주 가능 (offline 대비)
- **동적 유입 원칙**: 순서 무관 / 멱등 재색인 / 증분 편입(기존 건·새 건·비건)

---

## S6 — 반출 보안 설계 (화이트리스트) (7:30~8:00) · 30초

> "실제 사내 망에 붙일 때는, 반출을 막는 화이트리스트 설계가 전제입니다."

| 구분 | 허용 | 차단 |
|---|---|---|
| 질문 → 답변 | 사내 메일함 색인(indexed.json)만 | 인터넷·외부 서비스 호출 차단 |
| 첨부 내용 | 문서 텍스트 추출(로컬) | 첨부 파일·본문 외부 전송 금지 |
| LLM 호출 | 질문·후보 텍스트만 | 원본 mails.json·개인정보 전송 금지 |
| 데모 | 가상 데이터(무수정) | 실제 메일함 연동 없음 |

- **화이트리스트 근거**: 설계문서 '반출 보안 설계(화이트리스트)는 슬라이드에 포함 (발표용)' 요구
- **원칙**: 필요한 것만 통과시킨다 (deny by default)
