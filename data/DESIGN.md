# 가상 데이터 설계

실제 사내 메일함 스크린샷에서 추출한 말투를 그대로 계승한다.
**내용은 가상, 말투는 실물** — 심사자(같은 회사 임직원)가 화면을 보는 순간
자기 메일함을 떠올리게 하는 것이 데이터 품질의 유일한 기준이다.

## 계승할 말투 패턴 (실물에서 추출)

| 패턴 | 실물 예시 | 가상 데이터 적용 |
|---|---|---|
| `〔...〕` 대괄호 말머리 | `〔휴넷〕`, `〔SFA인턴〕` | 전체 제목의 약 70% |
| 이중 말머리 | `〔휴넷〕〔2026 법정필수〕...` | 시스템 발송에 적용 |
| 시스템 기계 발송 | 휴넷 8통 / 33통 (24%) | 전체의 25% |
| 접두사 대소문자 혼재 | `RE:` `Re:` `FW:` `Fw:` | 무작위 혼용 |
| **말머리 표기 흔들림** | `〔Project W_PI〕` vs `〔Project W PI〕` | **핵심 소재 — 아래 참조** |
| 수신자명 삽입 | `〔휴넷〕박○○님,〔2026 필수〕...` | 시스템 발송에 적용 |
| 날짜 그룹 헤더 | `어제` / `지난주` / `2주전` | UI에서 재현 |

## 가상 회사 설정

- **한결금융** (`hangyeol.co.kr`) — 금융권. 실물의 "금융권 정보보호(내근·위촉직)" 교육에서 유추
- **나**: 디지털전략팀 사원, 2025-09 입사 → 현재 입사 1년차
- **시스템 발신자**: `〔러닝포털〕` `〔그룹웨어〕` `〔정보보호센터〕` `〔인사시스템〕`
- **프로젝트**: `Project N_CX`(차세대 고객채널) · `D-MIG`(데이터 이관) · `ESG공시`

## 규모와 구성 (400통 / 30~40건)

| 분류 | 비중 | 성격 |
|---|---|---|
| 시스템 자동발송 | 25% | 교육 이수, 보안점검, 근태 — 제목이 거의 동일해 서로 구분 안 됨 |
| 공지·행정 | 15% | 전사 공지, 규정 개정, 총무 안내 |
| 팀 업무 | 40% | 프로젝트 진행, 요청·협조, 회의, 보고 |
| 교육·행사 | 15% | 워크숍, 멘토-멘티, 점심식사 스케줄 |
| 외부 | 5% | 협력사 견적·계약 |

## 시연의 중심이 되는 건(件) — 정성껏 만들 것

### 건 A: `Project N_CX` UI/UX 외주 업체 선정 (장면 1·2·3 전부 여기서)

```
05-04  〔Project N_CX〕UI/UX 외주 업체 선정 관련 협조 요청
05-07  RE: 〔Project N_CX〕UI/UX 외주 업체 선정 관련 협조 요청
05-12  〔Project N CX〕 업체 견적 취합본 공유드립니다        ← 표기 흔들림 + 첨부
05-14  FW: 견적 관련 문의드립니다                            ← 말머리 없음, 스레드 끊김
05-20  〔N_CX〕 최종 업체 확정 안내                          ← 축약 표기
```

**이 다섯 통이 하나의 건이라는 걸 메일함은 모른다.**

- `N_CX`로 검색 → `N CX`, `N_CX` 없는 2통 **누락**
- `견적`으로 검색 → 2통만 나오고, **어느 게 최종인지 알 수 없음**
- 금액은 첨부를 **열어야** 알 수 있음

→ 장면 1에서 심사자가 무엇을 검색하든 막힌다. **조작이 아니라 구조가 그렇다.**

### 건 B: Next W Workshop (첨부 속 개인 정보 찾기)
초대장 공유 → Re: 초대장 공유 → 버스 배차 및 최종 명단(첨부) → 회의 안내(Fw:)

### 건 C: 2026 필수교육 (자동발송의 무의미함)
`학습시작 안내` 4통(09-01) → `학습현황 안내` 4통(09-08).
**같은 교육의 경과인데 제목이 다르고, 4개 과정이 서로 구분되지 않는다.**
